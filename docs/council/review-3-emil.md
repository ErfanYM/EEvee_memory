New finding:
[should-fix] The white polaroid frame is a dead zone: only the photo window is tappable, though the whole print lifts on hover — css/main.css `.polaroid__open` covers only `.polaroid__window` (frame padding 10px sides, ~36px bottom) and js/lightbox.js binds click only to `.polaroid__open` (and js/video.js only to `.video__play` and `<video>`) — Chromium 390 touch: `img_7207` print 378px tall, photo 332px, tap on the bottom margin at 12px from the edge → dialog stays closed, tap on the photo → opens; Chromium 1440: click 14px inside the left edge of the cake print → closed, `elementFromPoint` = `.polaroid__tilt`. The bottom white band is about 10% of every card and the natural place for a thumb on a physical print; the hover lift on the border promises a click that does nothing. Fix: delegate from the figure so the whole print is the target: in lightbox.js `f.addEventListener('click', (e) => { if (!e.target.closest('.polaroid__open')) f.querySelector('.polaroid__open').click(); })` for photos; in video.js the same for `.polaroid--video` calling `start()` when `!v.hasAttribute('controls')` and the click is not on the `<video>`; add `.polaroid[data-kind="photo"] .polaroid__tilt, .polaroid--video:not(.is-playing) .polaroid__tilt { cursor: pointer; }`. Keep the button as the keyboard and screen-reader target (the figure listener is a pointer convenience only).
